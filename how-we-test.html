How we test

Updated November 28, 2026 · by Daniel Rojansky

Three kinds of AI visit a website, and each one sees a different page. A free scan tests all three. This page says exactly what we check, what we do not check, and where our rules come from.

Search crawlers

GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot and 10 more

We request your page as each bot and record what your server answers. Then we read the raw HTML with no JavaScript, because many crawlers do not run it.

This gives the 0 to 100 score: 9 areas such as robots.txt, structured data, content and brand signals.

Agents that read the page

Claude in Chrome, Perplexity Comet, ChatGPT agent

We open the page in headless Chrome at 1280 x 800 and read its accessibility tree: every heading, button, link and field with its name. That is the list these agents work from.

Agents that look at the screen

ChatGPT agent, Gemini in Chrome

In the same browser we take a screenshot when the page loads and mark every layer that covers it: cookie banners, newsletter pop-ups, chat windows and gates.

The agent checks

Pass counts 1, a warning counts half, a check that does not apply is left out. The share gives a grade from A (90% or more) to F (under 40%). The agent grade does not change the 0 to 100 score.

StepCheck and rule
FindSearch has a results page at its own address
A search box in a GET form, so results open at an address like /search?q=shoes. A search that only opens a pop-up fails.
FindEvery page has its own address
No #/ addresses that load the same page.
ReadEvery button and link has a name
The accessible name: visible text, aria-label, a label, or the alt text of an image inside. 1 to 2 missing is a warning, 3 or more fail.
ReadNames are clear and unique
3 or more buttons with the same name, or 3 or more links that only say Read more, give a warning.
ReadOne main heading names the page
Exactly one h1.
ActClickable things are real buttons and links
Boxes with a pointer cursor that are not buttons, links or form parts. 3 or more warn, 10 or more fail.
FormsForm fields have labels
A label, aria-label or aria-labelledby. Placeholder text alone does not count.
FormsFields say what they want
Email, phone and name fields need the right type and an autocomplete value.
Pop-upsNothing covers the page when it loads
Fixed layers over the screen at 1280 x 800. A layer over the middle, or over 30% of the screen, fails. A smaller one, or one with an unnamed close button, warns. A sticky menu bar and a small chat button are fine.
UnderstandContent does not change by itself
We read sliders twice, 2.5 seconds apart. A slider that changed by itself warns.
ShopPrices are text with a currency
Only when the page sells something (Product data or an Add to cart button).
ShopProduct data has price, currency and stock
Product JSON-LD with an Offer.
ShopStock is stated in words
In stock, Only 2 left, Sold out.
ShopAdd to cart is a named button
A button or link named Add to cart, Buy now or similar.

What we do not test

  • We read one page, once, without logging in. We never fill in a form, place an order or pay.
  • So we cannot see guest checkout, the full total before payment, payment fields or the order confirmation. The full report lists them as things to check by hand.
  • Agents change often. A pass here means the page follows what the agent makers publish today, not that every agent will finish every task.
  • Some sites block our browser. Then we say so, because they may block real agents too.

Agent readiness standards

Separately, we check 23 public standards for agents (robots.txt rules, Link headers, Markdown for agents, MCP and WebMCP and others) and rate them as a level from 0 to 5. These follow the rules that isitagentready.com (Cloudflare) documents.
